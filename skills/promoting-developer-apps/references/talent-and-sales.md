# Selling the app or selling talent

Two offers. Never blend them into one price card.

## Path 1 — Sell or license the app

Use when the user wants an exit, acquihire, or asset sale.

### Package the asset

- What is for sale: code, brand, domain, users, revenue, IP, app-store accounts
- Trailing 12-month revenue, margins, churn, traffic
- Stack, hosting cost, single-person risk
- Legal: licenses of dependencies, data privacy, who owns contractor work
- Transfer list: repos, domains, analytics, ad accounts, email lists, store listings

### Where buyers look

| Venue | Best for | Notes |
|-------|----------|-------|
| MicroAcquire / Acquire.com | Small SaaS | Clean metrics page |
| Flippa | Content, simple apps | Noisy; expect diligence |
| Empire Flippers / FE International | Larger cash-flow | Higher bar |
| Indie Hackers / X "for sale" | Tiny products | Warm audience first |
| Specialist brokers | Niche / higher price | Fees |
| Direct to competitor | Strategic buy | Quiet outreach |

### Pricing heuristic (not a valuation)

- <$10k MRR: often 24–42× monthly profit if growth is flat-to-up
- Content/app with no revenue: traffic × a conservative RPM, or rebuild-cost minus risk
- Always show last 3 months separately from a cherry-picked month

### Sale campaign

- Whisper: 10–20 targeted buyers, NDA after interest
- Signal: public listing + one founder post
- Pulse: listing + broker or two venues
- Blitz: rare; only with an advisor and a data room ready

Data room minimum: repo access plan, Stripe/P&L export, privacy policy, customer concentration, "how to run this in 30 days."

## Path 2 — Sell development talent

Use when the user is selling hours, a sprint, or an embedded role — not the product.

### Offer types

| Offer | Unit | Best channel |
|-------|------|--------------|
| Fixed-scope build | Milestone | Landing + proposal |
| Retainer / staff-aug | Monthly | LinkedIn + referrals |
| Emergency rescue | Week | Warm network, X |
| Advisory / fractional CTO | Monthly | LinkedIn, communities |
| Code audit / performance | Deliverable | Dev communities |
| Workshop / enablement | Day | Newsletter, LinkedIn |

### Positioning line

`{role} who {proof} for {ICP} so they {outcome}, unlike {generic freelancer}.`

Proof: shipped products, metrics, open-source, logos, before/after.

### Talent channels (keep separate from product ads)

**Free:** LinkedIn posts, X, Indie Hackers, relevant Discords, referrals, GitHub profile, personal site case studies, conference talks.

**Paid:** LinkedIn Ads to hiring titles, sponsored newsletters, niche job boards (We Work Remotely, Contra, Toptal application — not a media buy).

Do not buy generic "hire a developer" Google ads unless the landing page is a single offer with a calendar CTA.

### Talent sales assets

Write using [../assets/talent-offer.md](../assets/talent-offer.md):

1. One offer, one ICP, one price or range
2. 3 case studies (problem → work → number)
3. Scope in / scope out
4. Start date and capacity
5. CTA: calendar or email, not "let's chat sometime"

## Path 3 — App + talent together

Allowed only as **two SKUs**:

- Product license or sale
- Optional transition retainer (30/60/90 days)

Price them separately. Buyers discount mixed "I'll keep building it forever" promises.

## Honesty

- No fake logos or invented revenue.
- If metrics are thin, sell the rebuild-cost story or the talent path — do not invent MRR.
- Contractor IP must be assigned before a sale listing goes public.
