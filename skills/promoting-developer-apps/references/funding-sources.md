# Funding and crowdfunding

Use when the user needs money to build or grow. Keep this section separate from ad channels.

Ask: how much, by when, dilution tolerance, audience already in hand, and whether a product demo exists.

## Crowdfunding and pre-sales

| Source | Best for | What you owe back | Watch-outs |
|--------|----------|-------------------|------------|
| Kickstarter | Hardware, games, designed goods | Rewards, shipping, dates | Fees, failed-delivery reputation |
| Indiegogo | Similar, more flexible | Rewards or InDemand | Weaker discovery than KS |
| Crowd Supply | Open hardware | Fulfillment discipline | Niche, quality bar |
| iFundWomen / specialized | Underrepresented founders | Campaign + community | Smaller pools |
| Polar / Stripe / Lemon pre-orders | Software waitlists | Access, not equity | Refund policy in writing |
| Gumroad / Lemon pre-sales | Digital products | Deliverable date | Chargebacks |
| Patreon / GitHub Sponsors | Ongoing OSS | Recurring extras | Churn if you stop shipping |
| Open Collective | OSS + fiscal host | Transparency | Not a venture check |
| Ko-fi / Buy Me a Coffee | Tiny tools, goodwill | Nothing or extras | Not a plan for $50k+ |

Crowdfunding campaign must include: problem, demo, use of funds, reward ladder, risks, timeline, shipping or access plan.

## Equity, grants, and debt

| Source | Best for | Dilution | Notes |
|--------|----------|----------|-------|
| Friends and family | First $10–50k | High social risk | Write a simple note |
| Angels / syndicates | Seed with traction | Equity | Warm intro > cold form |
| Pre-seed / seed funds | Fast growth SaaS | Equity | Metrics they expect: waitlist, revenue, or usage |
| Accelerators (YC, Techstars, etc.) | Network + pressure | Equity | Apply only if you want that trade |
| Revenue-based (Pipe, Clearco-style, etc.) | Recurring revenue | None / fee | Needs existing sales |
| Bank / SBA / local debt | Asset-backed or cash-flow | None | Personal guarantee common |
| Corporate grants | Specific themes (AI, climate, civic) | Usually none | Slow, scoped |
| Public grants / SBIR / regional | Deep tech, research | Usually none | Heavy paperwork |
| Prize / hackathon funds | Early prototypes | None | One-time, noisy |
| Customer-funded (pilot contracts) | B2B | None | Best default for tools |

## How to choose

| Situation | First path |
|-----------|------------|
| Hardware or game, visual story | Crowdfunding |
| OSS with fans | GitHub Sponsors + pre-sales |
| B2B with 3 design partners | Customer-funded pilots |
| Consumer app, no revenue | Whisper more; do not raise on a deck alone |
| Needs $1M+ and growth | Equity, after Pulse-level proof |
| Wants no dilution | Pre-sales, grants, RBF if revenue exists |

## Pitch pack (always)

Write using [../assets/funding-pitch.md](../assets/funding-pitch.md):

1. Problem and who feels it
2. Product proof (demo, users, revenue)
3. Ask amount and 3-line use of funds
4. 12-month milestones
5. Offer (rewards, equity %, note terms, or grant scope)
6. Risks and "what if we miss"

## Campaign overlay

Funding needs distribution. After the pitch exists, run the main skill's channel plan:

- Whisper: 20 warm conversations, no public ask
- Signal: one public story + waitlist/pre-order page
- Pulse: page + email + 1–2 paid or sponsored hits
- Blitz: only with fulfillment capacity and a support plan

Do not send a cold investor a 20-channel ad plan. Send the pitch pack.
