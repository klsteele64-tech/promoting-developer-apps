# Document set

Write full prose. Each file must stand alone if opened first.

## Source: repo walk

Read README, package/manifest, routes or screens, env examples, tests named after features. List capabilities as user jobs.

## Source: interview

Use the promoting-developer-apps interview intake. Then write as if a new user landed from an ad.

## FACT-SHEET.md

```
# Fact sheet — {product}

## Confirmed
-

## UNKNOWN
-

## INFERRED (confirm before publish)
-
```

## README.md

1. Name + one-sentence job
2. Who it is for
3. First success (3–6 steps or a short clip link)
4. Install or open (link to getting-started)
5. Pricing or license
6. Links: docs, repo, support

Hero is 5–8 lines. No feature dump.

## getting-started.md

Numbered path a new user can finish in 10 minutes. Stop at the first success. Every UNKNOWN step is written as `UNKNOWN — do not skip` rather than invented clicks.

## features.md

One heading per user job. For each: what the user does, what they get, limit or price note if known.

## faq.md

At least five Q/A pairs from likely failures (install, auth of *their* app, pricing, data, "vs the substitute"). Answer UNKNOWN with UNKNOWN.

## changelog.md

```
# Changelog

## Unreleased

## {latest version or date}

```

Use customer language, not commit hashes.

## support.md

Contact path, hours if known, what to include in a report. UNKNOWN contact stays UNKNOWN.

## Save

Default directory: `docs/app/`. Overwrite only with user consent if files already exist.
